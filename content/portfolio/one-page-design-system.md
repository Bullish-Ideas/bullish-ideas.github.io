This working idea treats a design system as a set of shared decisions, not a collection of components. A first version can fit on one page if it records the choices people repeat.

## Record the basics

Start with a small palette for page surfaces, text, borders, and emphasis. Name a type family for headings and body text. Choose a short spacing scale, a readable content width, and a few rules for buttons and form controls.

Add one example for each decision. Show a heading beside body text. Show a primary button beside a text link. Include focused, disabled, and error states when people need to tell them apart.

## Write down when to use each choice

Values alone do not explain use. State where the accent color belongs, when a heading level should change, and how much space separates related content. Test the page at a narrow width and check text contrast before sharing it.

## Let repeated needs expand the system

Promote a pattern into a reusable component when it solves the same problem in several places. Keep unusual cases visible until they repeat. This avoids building a large library around decisions that may change.

A one-page system is a working agreement. Keep it small enough to revise and clear enough that another person can follow it.
